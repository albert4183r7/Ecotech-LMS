   273→## Phase 5 Changes (Task 5b — AI Course Generation)
   274→
   275→### Overview
   276→Replaced the placeholder/mock section generation in the Create Course page with real AI-powered content generation using `z-ai-web-dev-sdk` (GLM-4-Flash LLM).
   277→
   278→### 1. New API Route: `/api/generate-content` (route.ts)
   279→- **POST endpoint** accepting `{ topic, prompt, language? }`
   280→- Uses `z-ai-web-dev-sdk` LLM (GLM-4-Flash) on the server side only
   281→- System prompt instructs the AI to generate structured slide content as a JSON array
   282→- Supports both English and Chinese content generation
   283→- Generates 5-7 slides per section: 1 title slide, 3-5 content slides (mix of content/list/table/code types), 1 quiz slide
   284→- Quiz slide includes 4 answer options with the correct answer marked via `icon: "check"`
   285→- Robust JSON parsing: strips markdown code block wrappers, finds JSON array in response, validates structure
   286→- Fallback validation: ensures quiz has exactly 4 options, at least one correct answer, all slides have titles and valid types
   287→- Graceful error handling with user-friendly error messages
   288→
   289→### 2. Updated Create Course Page (`create-course-page.tsx`)
   290→- Replaced `handleGenerateSection` from `setTimeout` + `generatePlaceholderSlides` to async `fetch("/api/generate-content")`
   291→- Sends `{ topic: sectionName, prompt: sectionPrompt, language: sectionLanguage }` to the API
   292→- Parses AI response as `SlideContent[]` and populates the section draft fields
   293→- Loading state preserved via existing `generating` state + `Loader2` spinner in the Generate button
   294→- Toast notifications on success/error using `sonner`
   295→- No changes to UI layout or component structure — only the generation logic was swapped
   296→
   297→### Design Decisions
   298→- **Bilingual prompts**: System and user prompts are fully tailored for English vs Chinese, ensuring natural-sounding output
   299→- **Schema-first prompting**: The system prompt includes the exact SlideContent type schema so the LLM outputs conformant JSON
   300→- **Defensive parsing**: Multiple layers of JSON extraction (strip markdown, find array boundaries, validate/fallback) to handle LLM output variability
   301→- **Quiz correctness**: Guarantees exactly 4 quiz options with a marked correct answer, matching the interactive QuizSlide component expectations
   302→- **No new dependencies**: Uses existing `z-ai-web-dev-sdk` and project patterns

   370→## Phase 5 — Weekly Activity Chart & Streak Tracker (Task 5c)
   371→
   372→### Overview
   373→Added a weekly learning activity bar chart and streak tracker to the profile page. Includes a new API endpoint that returns daily activity data with realistic mock data fallback, a reusable ActivityChart component with pure-CSS bar visualization, and integration into the profile page between the Stats/Actions grid and the Team Leaderboard.
   374→
   375→### 1. New API Route: `/api/activity` (`src/app/api/activity/route.ts`)
   376→- **GET endpoint**: `/api/activity?userId=xxx&weeks=12`
   377→- **Parameters**: `userId` (defaults to `user_demo_001`), `weeks` (1-52, defaults to 12)
   378→- **Real data path**: Queries Progress table for records updated within the last N weeks, aggregates by date, estimates ~15-45 min per progress update
   379→- **Mock data fallback**: Seeded PRNG generates 7-12 weeks of realistic daily activity
   380→  - Weekdays: 85% active, 15-120 min per day, 10% chance of burst days
   381→  - Weekends: 65% active, 0-60 min per day
   382→- **Streak calculation**: Walks backward from today for current streak, full scan for longest streak (consecutive days with minutes > 0)
   383→- **Response shape**: `{ weeklyData: DayEntry[], streak: { current, longest }, totalMinutes }`
