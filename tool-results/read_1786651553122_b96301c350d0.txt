   272→## Phase 5 Changes (Task 5b — AI Course Generation)
   273→
   274→### Overview
   275→Replaced the placeholder/mock section generation in the Create Course page with real AI-powered content generation using `z-ai-web-dev-sdk` (GLM-4-Flash LLM).
   276→
   277→### 1. New API Route: `/api/generate-content` (route.ts)
   278→- **POST endpoint** accepting `{ topic, prompt, language? }`
   279→- Uses `z-ai-web-dev-sdk` LLM (GLM-4-Flash) on the server side only
   280→- System prompt instructs the AI to generate structured slide content as a JSON array
   281→- Supports both English and Chinese content generation
   282→- Generates 5-7 slides per section: 1 title slide, 3-5 content slides (mix of content/list/table/code types), 1 quiz slide
   283→- Quiz slide includes 4 answer options with the correct answer marked via `icon: "check"`
   284→- Robust JSON parsing: strips markdown code block wrappers, finds JSON array in response, validates structure
   285→- Fallback validation: ensures quiz has exactly 4 options, at least one correct answer, all slides have titles and valid types
   286→- Graceful error handling with user-friendly error messages
   287→
   288→### 2. Updated Create Course Page (`create-course-page.tsx`)
   289→- Replaced `handleGenerateSection` from `setTimeout` + `generatePlaceholderSlides` to async `fetch("/api/generate-content")`
   290→- Sends `{ topic: sectionName, prompt: sectionPrompt, language: sectionLanguage }` to the API
   291→- Parses AI response as `SlideContent[]` and populates the section draft fields
   292→- Loading state preserved via existing `generating` state + `Loader2` spinner in the Generate button
   293→- Toast notifications on success/error using `sonner`
   294→- No changes to UI layout or component structure — only the generation logic was swapped
   295→
   296→### Design Decisions
   297→- **Bilingual prompts**: System and user prompts are fully tailored for English vs Chinese, ensuring natural-sounding output
   298→- **Schema-first prompting**: The system prompt includes the exact SlideContent type schema so the LLM outputs conformant JSON
   299→- **Defensive parsing**: Multiple layers of JSON extraction (strip markdown, find array boundaries, validate/fallback) to handle LLM output variability
   300→- **Quiz correctness**: Guarantees exactly 4 quiz options with a marked correct answer, matching the interactive QuizSlide component expectations
   301→- **No new dependencies**: Uses existing `z-ai-web-dev-sdk` and project patterns

   369→## Phase 5 — Weekly Activity Chart & Streak Tracker (Task 5c)
   370→
   371→### Overview
   372→Added a weekly learning activity bar chart and streak tracker to the profile page. Includes a new API endpoint that returns daily activity data with realistic mock data fallback, a reusable ActivityChart component with pure-CSS bar visualization, and integration into the profile page between the Stats/Actions grid and the Team Leaderboard.
   373→
   374→### 1. New API Route: `/api/activity` (`src/app/api/activity/route.ts`)
   375→- **GET endpoint**: `/api/activity?userId=xxx&weeks=12`
   376→- **Parameters**: `userId` (defaults to `user_demo_001`), `weeks` (1-52, defaults to 12)
   377→- **Real data path**: Queries Progress table for records updated within the last N weeks, aggregates by date, estimates ~15-45 min per progress update
   378→- **Mock data fallback**: Seeded PRNG generates 7-12 weeks of realistic daily activity
   379→  - Weekdays: 85% active, 15-120 min per day, 10% chance of burst days
   380→  - Weekends: 65% active, 0-60 min per day
   381→- **Streak calculation**: Walks backward from today for current streak, full scan for longest streak (consecutive days with minutes > 0)
   382→- **Response shape**: `{ weeklyData: DayEntry[], streak: { current, longest }, totalMinutes }`
   383→
   384→### 2. New Component: ActivityChart (`src/components/lms/activity-chart.tsx`)
   385→- **7-day bar chart**: Pure CSS/Tailwind divs with height proportional to minutes
   386→- **Bar styling**:
   387→  - Active days: `oklch` gradient from teal to blue, intensity scales with minutes/maxMinutes ratio
   388→  - Inactive days: Subtle muted background bar (2px minimum)
   389→  - Rounded tops (`rounded-t-md`), max-width 40px per bar, 120px chart height
