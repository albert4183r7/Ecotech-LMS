   269→## Phase 5 Changes (Task 5b — AI Course Generation)
   270→
   271→### Overview
   272→Replaced the placeholder/mock section generation in the Create Course page with real AI-powered content generation using `z-ai-web-dev-sdk` (GLM-4-Flash LLM).
   273→
   274→### 1. New API Route: `/api/generate-content` (route.ts)
   275→- **POST endpoint** accepting `{ topic, prompt, language? }`
   276→- Uses `z-ai-web-dev-sdk` LLM (GLM-4-Flash) on the server side only
   277→- System prompt instructs the AI to generate structured slide content as a JSON array
   278→- Supports both English and Chinese content generation
   279→- Generates 5-7 slides per section: 1 title slide, 3-5 content slides (mix of content/list/table/code types), 1 quiz slide
   280→- Quiz slide includes 4 answer options with the correct answer marked via `icon: "check"`
   281→- Robust JSON parsing: strips markdown code block wrappers, finds JSON array in response, validates structure
   282→- Fallback validation: ensures quiz has exactly 4 options, at least one correct answer, all slides have titles and valid types
   283→- Graceful error handling with user-friendly error messages
   284→
   285→### 2. Updated Create Course Page (`create-course-page.tsx`)
   286→- Replaced `handleGenerateSection` from `setTimeout` + `generatePlaceholderSlides` to async `fetch("/api/generate-content")`
   287→- Sends `{ topic: sectionName, prompt: sectionPrompt, language: sectionLanguage }` to the API
   288→- Parses AI response as `SlideContent[]` and populates the section draft fields
   289→- Loading state preserved via existing `generating` state + `Loader2` spinner in the Generate button
   290→- Toast notifications on success/error using `sonner`
   291→- No changes to UI layout or component structure — only the generation logic was swapped
   292→
   293→### Design Decisions
   294→- **Bilingual prompts**: System and user prompts are fully tailored for English vs Chinese, ensuring natural-sounding output
   295→- **Schema-first prompting**: The system prompt includes the exact SlideContent type schema so the LLM outputs conformant JSON
   296→- **Defensive parsing**: Multiple layers of JSON extraction (strip markdown, find array boundaries, validate/fallback) to handle LLM output variability
   297→- **Quiz correctness**: Guarantees exactly 4 quiz options with a marked correct answer, matching the interactive QuizSlide component expectations
   298→- **No new dependencies**: Uses existing `z-ai-web-dev-sdk` and project patterns

   366→## Phase 5 — Weekly Activity Chart & Streak Tracker (Task 5c)
   367→
   368→### Overview
   369→Added a weekly learning activity bar chart and streak tracker to the profile page. Includes a new API endpoint that returns daily activity data with realistic mock data fallback, a reusable ActivityChart component with pure-CSS bar visualization, and integration into the profile page between the Stats/Actions grid and the Team Leaderboard.
   370→
   371→### 1. New API Route: `/api/activity` (`src/app/api/activity/route.ts`)
   372→- **GET endpoint**: `/api/activity?userId=xxx&weeks=12`
   373→- **Parameters**: `userId` (defaults to `user_demo_001`), `weeks` (1-52, defaults to 12)
   374→- **Real data path**: Queries Progress table for records updated within the last N weeks, aggregates by date, estimates ~15-45 min per progress update
   375→- **Mock data fallback**: Seeded PRNG generates 7-12 weeks of realistic daily activity
   376→  - Weekdays: 85% active, 15-120 min per day, 10% chance of burst days
   377→  - Weekends: 65% active, 0-60 min per day
   378→- **Streak calculation**: Walks backward from today for current streak, full scan for longest streak (consecutive days with minutes > 0)
   379→- **Response shape**: `{ weeklyData: DayEntry[], streak: { current, longest }, totalMinutes }`
   380→
   381→### 2. New Component: ActivityChart (`src/components/lms/activity-chart.tsx`)
   382→- **7-day bar chart**: Pure CSS/Tailwind divs with height proportional to minutes
   383→- **Bar styling**:
   384→  - Active days: `oklch` gradient from teal to blue, intensity scales with minutes/maxMinutes ratio
   385→  - Inactive days: Subtle muted background bar (2px minimum)
   386→  - Rounded tops (`rounded-t-md`), max-width 40px per bar, 120px chart height
   387→- **Hover tooltip**: Dark pill tooltip showing exact minutes, with CSS arrow pointer, `animate-in` entrance
   388→- **Today indicator**: Day label in primary color with a small dot below
   389→- **Streak badge**: "🔥 N day streak" in the header with CSS pulse animation, orange/amber gradient badge
   390→- **Summary footer**: Total minutes this week + "Best: N days" longest streak
   391→- **Loading skeleton**: Matches the card layout with randomized bar heights
   392→- **Accessibility**: `role="img"` with descriptive `aria-label` per bar
   393→- **Dark mode**: Uses `oklch` color values that work in both themes; foreground/background CSS variables
