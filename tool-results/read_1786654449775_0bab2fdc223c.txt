   275→## Phase 5 Changes (Task 5b — AI Course Generation)
   276→
   277→### Overview
   278→Replaced the placeholder/mock section generation in the Create Course page with real AI-powered content generation using `z-ai-web-dev-sdk` (GLM-4-Flash LLM).
   279→
   280→### 1. New API Route: `/api/generate-content` (route.ts)
   281→- **POST endpoint** accepting `{ topic, prompt, language? }`
   282→- Uses `z-ai-web-dev-sdk` LLM (GLM-4-Flash) on the server side only
   283→- System prompt instructs the AI to generate structured slide content as a JSON array
   284→- Supports both English and Chinese content generation
   285→- Generates 5-7 slides per section: 1 title slide, 3-5 content slides (mix of content/list/table/code types), 1 quiz slide
   286→- Quiz slide includes 4 answer options with the correct answer marked via `icon: "check"`
   287→- Robust JSON parsing: strips markdown code block wrappers, finds JSON array in response, validates structure
   288→- Fallback validation: ensures quiz has exactly 4 options, at least one correct answer, all slides have titles and valid types
   289→- Graceful error handling with user-friendly error messages
   290→
   291→### 2. Updated Create Course Page (`create-course-page.tsx`)
   292→- Replaced `handleGenerateSection` from `setTimeout` + `generatePlaceholderSlides` to async `fetch("/api/generate-content")`
   293→- Sends `{ topic: sectionName, prompt: sectionPrompt, language: sectionLanguage }` to the API
   294→- Parses AI response as `SlideContent[]` and populates the section draft fields
   295→- Loading state preserved via existing `generating` state + `Loader2` spinner in the Generate button
   296→- Toast notifications on success/error using `sonner`
   297→- No changes to UI layout or component structure — only the generation logic was swapped
   298→
   299→### Design Decisions
   300→- **Bilingual prompts**: System and user prompts are fully tailored for English vs Chinese, ensuring natural-sounding output
   301→- **Schema-first prompting**: The system prompt includes the exact SlideContent type schema so the LLM outputs conformant JSON
   302→- **Defensive parsing**: Multiple layers of JSON extraction (strip markdown, find array boundaries, validate/fallback) to handle LLM output variability
   303→- **Quiz correctness**: Guarantees exactly 4 quiz options with a marked correct answer, matching the interactive QuizSlide component expectations
   304→- **No new dependencies**: Uses existing `z-ai-web-dev-sdk` and project patterns
