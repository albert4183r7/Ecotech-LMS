   274→## Phase 5 Changes (Task 5b — AI Course Generation)
   275→
   276→### Overview
   277→Replaced the placeholder/mock section generation in the Create Course page with real AI-powered content generation using `z-ai-web-dev-sdk` (GLM-4-Flash LLM).
   278→
   279→### 1. New API Route: `/api/generate-content` (route.ts)
   280→- **POST endpoint** accepting `{ topic, prompt, language? }`
   281→- Uses `z-ai-web-dev-sdk` LLM (GLM-4-Flash) on the server side only
   282→- System prompt instructs the AI to generate structured slide content as a JSON array
   283→- Supports both English and Chinese content generation
   284→- Generates 5-7 slides per section: 1 title slide, 3-5 content slides (mix of content/list/table/code types), 1 quiz slide
   285→- Quiz slide includes 4 answer options with the correct answer marked via `icon: "check"`
   286→- Robust JSON parsing: strips markdown code block wrappers, finds JSON array in response, validates structure
   287→- Fallback validation: ensures quiz has exactly 4 options, at least one correct answer, all slides have titles and valid types
   288→- Graceful error handling with user-friendly error messages
   289→
   290→### 2. Updated Create Course Page (`create-course-page.tsx`)
   291→- Replaced `handleGenerateSection` from `setTimeout` + `generatePlaceholderSlides` to async `fetch("/api/generate-content")`
   292→- Sends `{ topic: sectionName, prompt: sectionPrompt, language: sectionLanguage }` to the API
   293→- Parses AI response as `SlideContent[]` and populates the section draft fields
   294→- Loading state preserved via existing `generating` state + `Loader2` spinner in the Generate button
   295→- Toast notifications on success/error using `sonner`
   296→- No changes to UI layout or component structure — only the generation logic was swapped
   297→
   298→### Design Decisions
   299→- **Bilingual prompts**: System and user prompts are fully tailored for English vs Chinese, ensuring natural-sounding output
   300→- **Schema-first prompting**: The system prompt includes the exact SlideContent type schema so the LLM outputs conformant JSON
   301→- **Defensive parsing**: Multiple layers of JSON extraction (strip markdown, find array boundaries, validate/fallback) to handle LLM output variability
   302→- **Quiz correctness**: Guarantees exactly 4 quiz options with a marked correct answer, matching the interactive QuizSlide component expectations
   303→- **No new dependencies**: Uses existing `z-ai-web-dev-sdk` and project patterns
